Where this goes next

Hackathon build is a single-page demo. Production runs on Microsoft 365, which the team already uses, so there is no new login to manage and no new place to store people's data.

How each piece maps to Microsoft 365

Identity / login
Microsoft Entra ID (Azure AD). Nobody creates a new account; they use their existing work sign-in. Identity also tells the app which person's sheet to load, so privacy is automatic.
Data store
A SharePoint list, one item per person per month. Holds the daily codes, computed allowance, status (Draft / Submitted / Approved / Needs Correction), manager comments, and a full timestamped history for audit.
The app itself
Same front end you're demoing, hosted as a SharePoint / Teams app (or Power Apps if you want low-code). Lives inside a tab in Teams so the team opens it where they already work.
Approval workflow
Submit is blocked until the window opens (1st of the following month) and flagged late after the 7th business day. Manager can Approve, Send back with a comment (auto-unlocks the employee's sheet), or edit the entries directly and save as a correction.
Business rules
Rate card, code validation, the submission-window dates, and the weekend premium logic move server-side (Power Automate or a small Azure Function) so none of it can be bypassed from the browser.
Notifications
Real push, not the in-app badge this demo uses: Power Automate sends the manager a Teams/email alert on every new submission, and sends the employee an alert when approved or sent back for correction.
Manager reporting & export
The formatted Excel export in this demo is designed to become an automated step: on approval, Power Automate drops that month's sheet into the team's tracked SharePoint workbook as a new monthly tab, so the workbook stays the single source of truth without anyone copy-pasting.
Reminders
Power Automate flow: nudge anyone who hasn't submitted as the 7-business-day deadline nears, and notify the manager once everyone's in or once anything's overdue.

Rollout in three phases

Phase 1
Lift this UI into a Teams tab backed by a SharePoint list. Manual sign-in, real per-person storage. Ships in days.
Phase 2
Move rate/validation logic server-side, add the submission-cutoff reminders and manager notifications.
Phase 3
Power BI dashboard, month rollover automation, and a payroll-ready export or direct handoff.
Why M365 over a standalone app: the data never leaves your tenant, there's no separate password for the team to forget, and IT already governs it. The hackathon version proves the workflow; this is the same thing on rails the org already trusts.
